# Синтетические данные для тестовых проектов

Все значения в этой папке вымышлены. Они предназначены только для локальной или изолированной тестовой среды и не являются замерами объекта, условиями аэропорта/больницы или характеристиками робота. Не используйте их для коммерческого расчёта или реального планирования.

## Файлы

- `object-profile-warehouse.csv`, `object-profile-airport.csv`, `object-profile-hospital.csv` — импортируемые дополнительные параметры объекта. Загружайте файл, соответствующий типу проекта.
- `operation-log-transport.csv` — синтетические поступления транспортных заданий; каждая строка равна одному рейсу.
- `operation-log-cleaning.csv` — синтетические задания уборки; `work_units` задаёт площадь в м².
- `availability-calendar-synthetic.csv` — календарь трёх синтетических слотов для текущего тестового проекта и его стартовой точки. Для другого проекта нужен его собственный `ready_at_node` и период журнала.

Объектный CSV имеет точный формат: `object_slug;label;unit;value;min;max;source`. Сохраните файл в UTF-8 и не меняйте код объекта. В каждом `source` прямо помечено, что значение синтетическое.

## Загрузка

1. В приложении создайте проект нужного типа: склад, аэропорт или медицинское учреждение. Для первого прогона удобно назвать его `ТЕСТ — склад (синтетические данные)`.
2. В проекте откройте «Импорт параметров», выберите соответствующий `object-profile-*.csv`, нажмите предварительный просмотр, проверьте, что ошибки отсутствуют, затем сохраните новую ревизию. Эти строки сохраняются как дополнительный паспорт объекта; сами по себе они не задают операцию, маршрут или расчётный спрос.
3. В «Задаче и подборе» выберите операцию и внесите тестовые значения из таблицы ниже. В поле источника у каждого значения укажите `Синтетический тестовый сценарий из examples/project-test-data/README.md`. Подтверждение отмечайте только для явно тестового проекта.
4. В маршруте добавьте точки и соединения. Для безопасного первого теста склада: точка `Зона хранения`, точка `Передача груза`, уровень `1`; соединение длиной `40` м, источник `Синтетический тестовый маршрут, не измерение`; включите движение в обе стороны и задайте маршрут от хранения к передаче.
5. В списке моделей выбирайте только модель со статусом «Подходит», если хотите пройти к расчёту парка. Статус «Требуется проверка» не означает подтверждённую пригодность; он может блокировать расчёт.
6. В «Парке роботов» введите эксплуатационные показатели из примера ниже и такой же синтетический источник для каждого поля. Сохраните показатели.
7. В «Журнале заданий» загрузите подходящий CSV: для перевозки — `operation-log-transport.csv`, период `2026-09-29T08:00:00+03:00` — `2026-09-29T10:00:00+03:00`; для уборки — `operation-log-cleaning.csv` с тем же периодом. В описании источника укажите, что журнал синтетический. Персональные данные и реальные идентификаторы в журнал не добавляйте.
8. В календаре роботов загрузите `availability-calendar-synthetic.csv`, укажите синтетический источник и подтвердите интервалы. Файл покрывает весь тестовый период и ставит каждый слот в начальную точку маршрута.
9. Откройте симуляцию и запустите прогон. Если страница сообщает, что данных не хватает, сначала проверьте сохранённую операцию, выбор модели, измеренную топологию, показатели парка и календарь.

## Тестовые значения для формы операции

Все источники ниже задайте как `Синтетический тестовый сценарий, не измерение объекта`.

| Тип и операция | Поля операции |
| --- | --- |
| Склад — перемещение паллет | Масса паллеты с грузом: `500 кг`; самый узкий участок маршрута: `1800 мм`; передача паллеты: `platform_transfer` |
| Аэропорт — перевозка багажа | Масса буксируемого состава: `650 кг`; требуемое тяговое усилие: `450 Н`; самый узкий участок: `2200 мм` |
| Аэропорт — уборка терминала | Самый узкий участок: `2000 мм`; площадь уборки: `1500 м²` |
| Больница — доставка питания | Масса тележки: `80 кг`; длина: `1200 мм`; ширина: `650 мм`; самый узкий участок: `1600 мм` |
| Больница — уборка помещений | Самый узкий участок: `1600 мм`; площадь уборки: `2400 м²` |

Для склада способ передачи паллеты — тестовое допущение. Для аэропорта у соединений обязательно задайте режим доступа; для больницы — тип перехода и санитарный поток, а между этажами используйте лифт. Эти сценарии не подтверждают реальную безопасность или применимость.

## Тестовые значения для парка

Для транспортной операции: пиковый поток `4 рейса/ч`, рабочая скорость `0.8 м/с`, загрузка `30 с`, передача груза `20 с`, плановая доля времени на задания `0.75`, техническая готовность `0.90`, работа от заряда `6 ч`, полная зарядка `2 ч`.

Для уборки: пиковая нагрузка `650 м²/ч`, измеренный для теста темп уборки `500 м²/ч`, плановая доля времени на задания `0.75`, техническая готовность `0.90`, работа от заряда `6 ч`, полная зарядка `2 ч`.

Поля заполняются в интерфейсе, не импортируются объектным CSV. Если выбранная модель имеет меньшую подтверждённую скорость или не проходит другие ограничения, подберите меньшую тестовую скорость либо оставьте результат как требующий проверки; не меняйте подтверждённые характеристики модели.

## Важно о границах импорта

Сейчас CSV загружает только дополнительные поля паспорта объекта и журнал поступлений заданий. Параметры операции, топология маршрута и показатели парка вводятся в соответствующих формах проекта. Файлы журнала демонстрационные, и их нельзя принимать за фактический журнал объекта.
