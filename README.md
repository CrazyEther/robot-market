# robot-market

Русскоязычная веб-платформа предварительного проектирования роботизации **склада, аэропорта и медицинского учреждения**. Реализуется на Django/Python и PostgreSQL. Эти три объекта имеют одинаковый обязательный объём будущей реализации, но отдельные процессы, маршруты и ограничения.

**Текущее состояние:** первый демонстрационный срез. Работают выбор трёх объектов, отдельные страницы, API паспортов сценариев, PostgreSQL-схема и диагностические endpoints. Параметры и топологии синтетические; сопоставление с реальными роботами, расчёты парка, ROI и имитация пока не реализованы. Не используйте демо в качестве инженерного заключения.

## Запуск

При установленном Docker с Compose в корне репозитория:

```sh
docker compose up --build -d
```

Открыть http://localhost:8000. API: `/api/v1/objects/`, `/api/v1/objects/warehouse/`, `/api/v1/objects/airport/`, `/api/v1/objects/hospital/`. Проверка приложения: `/health`; проверка подключения к БД и схемы: `/ready`. Для остановки: `docker compose down` (том БД сохраняется). Порт меняется через `WEB_PORT`.

Запуск без Docker для разработки на Python 3.11+:

```sh
python -m venv .venv
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

Локально без `DATABASE_URL` используется SQLite только для разработки. В Docker и предпросмотре применяется PostgreSQL. Для самостоятельного запуска с PostgreSQL установите `DATABASE_URL` и локальные `DEBUG=1`, `DJANGO_SECRET_KEY`. Значения из `.env.example` служат только примером локальной конфигурации.

Проверка:

```sh
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test
```

## Разработка и статусы

Требуемый полный путь для **каждого** объекта: ввод/импорт → каталог и обоснование применимости → топология и парк → baseline/purchase/RaaS → what-if → событийная 2D-симуляция → сохранение/открытие → PDF/CSV. Ничего из расчётных этапов пока нельзя считать выполненным. См. [состав продукта](docs/PRODUCT.md), [план задач](docs/WORK_ITEMS.md) и [условия онлайн-развёртывания](docs/DEPLOY.md).

В репозиторий включены только собственный код, синтетические примеры и общедоступное описание интерфейса. Закрытые входные материалы и оригинальные конкурсные документы не публикуются. Отсутствующие параметры оборудования обозначаются `missing`, синтетические — `assumption`, а не нулём и не подтверждённой применимостью.
