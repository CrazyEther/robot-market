# План реализации интерфейса на Django

Порядок визуальной реализации в действующем Django приложении. Этот файл описывает проверяемые работы и не является вторым tracker задач. Состояние реализации подтверждается кодом, тестами и осмотром страниц.

## Для последующих продуктовых задач

Следующие задачи переиспользуют токены, формы, статусы, таблицы и отображение источников. Предметные модели, финансовое сравнение, событийная симуляция и экспорт добавляются вместе с действующими серверными контрактами. Каждый новый экран получает нормальное, пустое, ошибочное и неизвестное состояния; права пользователя проверяются на сервере. Кнопка действия появляется вместе с backend-действием.

## Доказательство результата

Для каждого шага сохранить до/после на desktop и mobile; проверить Django tests и HTTP пути трёх объектов. Для финального среза дать screenshots всех трёх объектов, список источников ассетов, результат клавиатурной и контрастной проверки, `git diff --check` и проверенный preview, когда он доступен. Внешнее сходство с референсами не служит acceptance oracle; проверяется собственный интерфейс и пользовательская задача.
