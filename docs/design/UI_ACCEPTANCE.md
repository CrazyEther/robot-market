# Критерии приёмки дизайн-среза

Критерии визуального среза и последующей регрессии. Факт прохождения проверок фиксируется отдельно от этого списка.

1. На главной за 5 секунд понятны назначение платформы, три равноправных объекта и переход к каждому. На экране объекта виден его процесс, требуемые входные параметры и следующий шаг; конкретные единицы и происхождение значений показываются после загрузки параметров объекта.
2. Все действующие ссылки, API URL, импорт каталога и тесты продолжают работать. Визуальный слой не показывает подбор, ROI, симуляцию или экспорт как работающие до реализации соответствующих задач.
3. Проверены desktop 1440×900 и 1366×768, планшет около 768 px, мобильный 390×844 и узкий экран 320 px: нет горизонтальной прокрутки основных страниц; контент не перекрывается, карточки и таблицы остаются читаемыми. Для будущих широких таблиц допускается явно обозначенная прокрутка внутри таблицы.
4. Навигация, кнопки и формы доступны с клавиатуры; видимый focus, логичный порядок tab, семантические заголовки/labels, текстовые имена ссылок. Контраст текста и интерактивных элементов проверен по WCAG AA, цель обычного текста 4.5:1; для крупного 3:1.
5. `prefers-reduced-motion` убирает необязательные переходы. Ни одна анимация не мешает чтению или вводу. На медленной сети страница остаётся полезной до загрузки медиа; отсутствующие изображения не ломают layout.
6. `missing`, `assumption`, `requires_verification`, `fit`, `reject` различимы по тексту и смыслу; неизвестная цена не рендерится как `0 ₽`. Ошибка ввода показывает поле, единицу и способ исправления.
7. В каталоге цена с валютой появляется только для точной модели и условий из проверенного коммерческого источника; порог партии, период аренды и отдельные услуги видны рядом с суммой. Покупательские карточки не показывают имя CSV, SHA-256, номер строки, диагностику парсинга или внутренний статус отсутствующего поля. Если первичная страница производителя относится лишь к бренду, ссылка подписана как сайт производителя, а не страница модели.
8. На трёх объектах с подтверждёнными входами проверена одинаковая глубина представления: склад, аэропорт, медучреждение. На мобильном и desktop проверен путь выбора объекта, открытия страницы и API. Для визуальной проверки без объектных данных используются только собственные схемы интерфейса, без вымышленных деловых значений.
9. При публикации PR приложены собственные снимки экранов трёх размеров, краткое описание дизайн-решений, происхождение новых ассетов, результат Django tests и ручная проверка клавиатуры. Материалы референсов не копируются в репозиторий.
