# Рабочая карточка: ресурсная событийная симуляция v3

Цель для пользователя: задержка робота на подтверждённом общем участке должна влиять на 2D/3D движение, доставку, KPI, расчёт экономики и экспорт.

Связанное требование: docs/PRODUCT.md, пп. 3–7; склад, аэропорт и медучреждение. Issue: T14–T16, интеграционный gate T20. Ветка: checkpoint/2026-09-27-full-work, базовый HEAD 2ae9c29.

Scope IN: переключение v2/v3 по подтверждённому ресурсу в сохранённой топологии; воспроизводимость и защита снимка; отрисовка индивидуальных фаз; метрики занятости; экспорт; регрессионные тесты. Scope OUT: синтез тарифов, неподтверждённые ограничения площадки, новый 3D-движок, восстановление каталога (следующая задача).

Входы и контракты: неизменяемый scenario snapshot, исходные CSV задания/календаря с SHA-256, build_route_resources, schedule_resource_jobs, SimulationRun. Версия ядра и план источников закрепляются в run.input_snapshot; старый ledger v2 сохраняет прежнюю реализацию.

Acceptance: для каждого объекта подтверждённый общий ресурс влияет на время доставки и не допускает недопустимых пересечений; повторное открытие детерминировано, подмена plan/ledger отклоняется; 2D, 3D и SVG показывают ожидание; метрики, финансы и экспорт ссылаются на один верифицированный ledger; без ресурсов действует v2.

Проверка: Django tests на ядро, интеграцию, финансы/экспорт и три предметных процесса; `manage.py check`; `manage.py makemigrations --check --dry-run`; `git diff --check`. При провале сохранять исходные данные, корректировать ограниченный контракт и повторить тесты.

Риск: изменённый существующий worktree. План отката: адресные изменения этой карточки без переписывания чужих файлов. Следующий gate: проверка на реальных исходных параметрах площадки; затем восстановление полного каталога с происхождением каждой позиции.

Ревью 28.09: найдено несоответствие допустимого расписания в форме и ядре; форма теперь отклоняет текстовые/пересекающиеся окна до сохранения. Проверка короткого горизонта доказала, что занятость прохода меняет доставленный объём, а не только визуализацию. На контрольном локальном замере 3 000 задач с двумя роботами и одним ресурсом выполнялись за 13,604 с. Узкий дополнительный пункт этой карточки: ускорить поиск пересекающихся бронирований без изменения байтового результата для контрольного DES-набора; повторить тесты трёх объектов, финансы и архивный replay.
