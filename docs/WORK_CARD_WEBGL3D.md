# Рабочая карточка: пространственное воспроизведение сохранённого прогона

Цель для пользователя: вместо плоской проекции показывать действительную WebGL-сцену с объёмными уровнями, маршрутом, роботами, ожиданием общих участков и вертикальным движением лифта.

Связанное требование: `docs/PRODUCT.md`, раздел «Доступные средства анализа сохранённого прогона»; T14–T16 и T20, три типа объекта. Ветка `checkpoint/2026-09-27-full-work`, базовый HEAD `2ae9c29`.

Scope IN: самостоятельный локально обслуживаемый 3D-renderer, камера/масштаб/ресайз, объёмные маркеры, 3D-интерполяция лифта, fallback для браузера без WebGL; один вход из проверенного playback. Scope OUT: новые ТТХ/тарифы/топологии, физическая модель столкновений и навигация по свободному пространству, изменение ядра DES и его финансов.

Инварианты: v2/v3 и 2D используют неизменённый журнал; координаты источника определяют схематическое положение узлов, а высота этажей и размер маркера явно условны; без WebGL работает прежняя схема; сторонняя библиотека поставляется локально с лицензией.

Acceptance: реальный контекст WebGL и его геометрия проверены браузером; робот перемещается между этажами в фазе `elevator` и неподвижен в `resource_wait`; 2D, KPI, версия события и отчёт не меняются; fallback доступен при отказе WebGL; проверены JS, Django и browser smoke без подмены исходного сценария.

Риски: GPU/контекст WebGL могут быть недоступны в части окружений, поэтому сохраняется Canvas fallback. Движение по рёбрам схематично и не свидетельствует о физической пригодности робота или точной геометрии площадки. Следующий gate: независимое ревью diff и эксплуатационная проверка трёх объектов.

## Свидетельства проверки (28.09.2026)

- Пространственный рендер: собственный `static/projects/webgl3d.js` и локальный MIT `three@0.186.1`. Загрузка WebGL2 происходит после открытия 3D-вкладки. `static/projects/scene3d.js` оставляет прежний Canvas fallback при отсутствии WebGL2 и после потери GPU-контекста.
- Согласование данных: `projects/playback.py` отдаёт ключ ресурса на рёбрах и устойчивые ID переходов между этажами; `static/projects/playback.js` отправляет в 3D занятость ресурса из того же верифицированного журнала, что используется для текстового KPI. Поведение ядра DES/финансовых формул не менялось.
- Проверка в Playwright: `ROBOT_MARKET_BASE_URL=http://127.0.0.1:8013 .\.venv\Scripts\python.exe tools\smoke_webgl.py` (в PowerShell установить переменную через `$env:`). Фактически прошли загрузка WebGL2, этажный переход, ожидание, занятость ребра, изменение камеры, удаление/повторное создание маркера, потеря контекста и fallback. Снимок тестового рендера сохраняется вне Git во временной директории ОС.
- Дополнительная браузерная приёмка на **настоящем HTML сохранённого прогона v3**: `$env:ROBOT_MARKET_BROWSER_E2E='1'; .\.venv\Scripts\python.exe manage.py test projects.test_webgl_live`. Используется только изолированная Django test database и контрольный тестовый граф; прошли переключение 2D/3D, движение после сохранённого события, состояние ресурса, неизменность счётчиков и responsive 390 px. Без переменной этот необязательный тест пропускается, если Chromium не установлен в CI.
- Профильная интеграция `projects.test_resource_integration` проверяет, что HTTP страницы после повторного открытия содержит v3 движение, ресурсы и связь рёбер с источником. Исторический v2 остаётся читаемым. **Последний полный прогон после всех исправлений: 125/125, OK (48,845 с)** с env-путями и контрольными суммами закрытых источников и `ROBOT_MARKET_BROWSER_E2E=1`. Оба браузерных профиля (`tools/smoke_webgl.py` и `projects.test_webgl_live`) прошли, Django system check и миграции без изменений, `node --check` для трёх JS, `git diff --check` без ошибок. Результат относится к локальному тестовому окружению; CI, HTTPS и натурные измерения не проверены.

Ревью кода в текущей сессии: Three.js разделяет геометрию спрайта между экземплярами; удаление одного робота больше не освобождает её для всех подписей этажей. На межэтажных переходах координаты выбираются по уникальному ID узла, а не по потенциально повторяющемуся тексту подписи. Внешнее независимое ревью diff ещё не проведено. Остаточный риск: геометрическая схема этажей нормализуется отдельно для визуализации, поэтому она **не** проверяет физические расстояния и столкновения в реальном 3D; для этого требуются план/габариты/масштаб и дополнительные предметные модели, подтверждённые владельцем объекта.
