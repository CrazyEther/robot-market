# ADR-0002: выбор робота закрепляется за точной исходной записью

Дата: 25.09.2026. Статус: принято для контракта ревизий проекта.

## Контекст

Один исходный ID каталога v4 может относиться к нескольким областям применения и предложениям. Пользовательский выбор семейства без точной строки и версии источников допускает незаметную смену комплектации или условий после обновления каталога. Изменение задачи либо паспорта объекта может изменить результат подбора.

## Решение

Действие выбора обрабатывается сервером для владельца проекта и актуальной ревизии. Сервер повторно вычисляет кандидатов из закреплённого `CatalogEvidenceBatch` и принимает только точный `CatalogSourceRow.record_index`, присутствующий в результатах для сохранённого процесса. Статус `reject` блокирует выбор. `requires_verification` сохраняется как кандидат для уточнения условий и не является допуском к численному расчёту.

Новая `ProjectRevision.scenario_snapshot.robot_selection` сохраняет контрольные суммы v4 и реестра, номер строки, исходный ID, название модели, производителя, все связанные утверждения о применении, версию алгоритма, проверенный статус, коды причин, ссылки на подтверждения, пользователя и время. Предыдущая ревизия остаётся неизменной. При изменении `task_profile` или `input_profile` активный выбор удаляется из нового снимка.

## Последствия

В интерфейсе можно вернуться к историческому выбору и его источникам. Расчёт парка, симуляция и экономика в будущих модулях должны требовать `fit` и отдельно проверять актуальность выбранной ревизии. Для изменения правил matcher требуется новая версия алгоритма и контрактная проверка старых сохранённых результатов. Каталожная цена остаётся отдельным атрибутом предложения; выбор модели сам по себе не фиксирует коммерческий договор.
