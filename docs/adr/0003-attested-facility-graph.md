# ADR-0003: топология объекта в неизменной ревизии

Дата: 25.09.2026. Статус: принято для маршрутов проекта.

## Контекст

Открытые кейсы производителей подтверждают отдельные зоны и иногда длину маршрута, но не задают планировку помещения заказчика. Координата на плане сама по себе не подтверждает проходимый участок, а существование прохода не доказывает его длину. Склад, аэропорт и больница требуют разных ограничений на путь.

## Решение

`scenario_snapshot.topology_profile` версии 1 хранит заданные владельцем точки, явные направленные/двусторонние соединения, выбранные концы маршрута и происхождение каждого измерения. Координаты и длины допускают отсутствие; `null` не заменяется нулём. Каждое изменение создаёт новую `ProjectRevision`, прежняя остаётся неизменной. Смена процесса удаляет топологию из новой ревизии; изменение параметров той же операции её сохраняет.

Маршрут существует только по явно сохранённым соединениям. Режимный участок аэропорта не допускается в путь без отдельного контракта подтверждённых полномочий. В больнице переход между этажами возможен только по лифтовому ребру, а участок и зоны должны соответствовать выбранному санитарному потоку. При отсутствии измеренной длины хотя бы одного участка результат остаётся без численного расстояния. 2D SVG строится только из введённых пар координат; этажи не смешиваются на одном слое. Никакой слой не генерирует координаты из названий зон или публичных кейсов.

## Последствия

Текущий путь доказывает связность и сумму измеренных участков выбранной цепочки, но ещё не является проверкой габаритов, времени, нагрузки и числа роботов. Для допуска режимного маршрута необходим отдельный документированный договор доступа объекта и подтверждённая совместимость конкретной модели; для медицинского цикла потребуются ожидание лифта и санитарные регламенты. Sizing и событийная симуляция должны читать закреплённую ревизию и отказываться от численного результата, пока эти входы отсутствуют.

## Уточнение времени межэтажной доставки · 26.09.2026

`length_m` лифтового ребра описывает геометрию маршрута, а не длительность поездки; рабочая скорость робота на горизонтальном участке к лифту не применяется. Для каждого плеча с одним межэтажным переходом `workload_profile.parameters` хранит отдельно измеренное ожидание и измеренную поездку лифта в секундах, с источником. Полный цикл и момент передачи груза складывают горизонтальный путь по рабочей скорости, загрузку/выгрузку и эти интервалы. 2D воспроизведение использует те же интервалы. Старая ревизия без времени поездки не получает новый численный цикл. При нескольких переходах на одном плече требуется документированное время каждого лифтового ребра; агрегированная пара не распределяется по переходам произвольно. Отсутствие лифта на плече даёт нулевое лифтовое время из подтверждённой топологии, без пользовательской подстановки.
