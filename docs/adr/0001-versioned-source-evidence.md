# ADR 0001: версии каталога и первичных сведений

Дата: 25.09.2026. Статус: принято для текущего контракта данных.

## Контекст

Конкурсный каталог v4 содержит предложения, но не подтверждает критичные ТТХ, валюту и НДС. Публичные страницы производителей и описания внедрений могут изменяться. Повторное открытие проекта не должно незаметно использовать новые цены или паспортные значения.

## Решение

- Исходный v4 и сырые HTTPS-снимки хранятся вне публичного Git. Сбор и сверка доказательств выполняются отдельным процессом `tools/source_research/`.
- `CatalogBatch` сохраняет каждую исходную строку, цену и checksum CSV. `CatalogEvidenceBatch` сохраняет checksum проверенного реестра утверждений; отдельные `CatalogEvidenceClaim` связываются с точными строками v4 и содержат источник, время получения, область действия и статус использования.
- При создании проекта оба checksum записываются в ревизию. Редактирование параметров сохраняет эти версии. Переход из проекта в каталог передаёт обе версии; запрос несуществующей или несоответствующей версии даёт 404.
- Отсутствующее или конфликтующее значение остаётся неизвестным. Кейсы и рекламные предложения не становятся универсальным ограничением применимости, тарифом или экономическим результатом.

## Следствия

Запуск требует разрешённые файлы и проверенные SHA-256; без них сервис не отвечает как готовый. Новые версии источников создают новые пакеты, а старые остаются доступны для ревизий. Для итогового расчёта нужно дополнительно сохранять полный снимок использованных входов и правил модели; одних checksum недостаточно для самодостаточного отчёта вне базы данных.

## Закрытая загрузка и аудит, уточнение 26.09.2026

Сырые байты каталогового CSV и реестра сведений сохраняются в закрытой БД вместе с SHA-256. Для пакетов, созданных до появления этого поля, тот же исходный файл с тем же checksum можно загрузить повторно: данные пакета не изменятся, а исходные байты будут архивированы. БД и её резервные копии относятся к закрытому контуру; публичный каталог не отдаёт исходные файлы.

Веб-загрузка доступна только сотруднику с обоими разрешениями импорта Django. Введённая контрольная сумма должна совпадать и с байтами файла, и с утверждённой суммой `CATALOG_SOURCE_SHA256` или `RESEARCH_CLAIMS_SHA256` окружения. Конкурсный CSV не исправляют на месте: уточнения цены, комплектации и ТТХ поступают новым реестром первичных сведений, привязанным к точной записи v4. Успешное действие фиксирует аккаунт, источник, checksum, основание права обработки и время. Django admin предоставляет только чтение исторических записей.

При миграции с прежней схемы существующая витрина закрепляется за `CatalogPublication`. Начальный импорт через CLI при развёртывании также закрепляет первую версию; повторный CLI-импорт её не переключает. Загрузка через закрытый веб-интерфейс только сохраняет пакет, включая первый пакет в пустой БД: сотрудник с `change_catalogpublication` публикует его отдельным действием с причиной. Публичный запрос по checksum не открывает ещё не опубликованную версию; ранее опубликованные версии остаются доступны сохранённым проектам. Переключение обратно на старый пакет создаёт новую запись журнала публикаций без изменения байтов исходника, claim или сохранённого проекта. Новые проекты выбирают опубликованный пакет; старые ревизии сохраняют свои checksum.
