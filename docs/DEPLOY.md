# Развёртывание первой версии

## Локально

`docker compose up --build -d` запускает PostgreSQL и Django. Web и API обслуживаются одним процессом Django по порту 8000. БД хранится в отдельном Docker-томе. `/health` отвечает при работающем web; `/ready` требует связи с БД, импортированного каталога v4 и проверенного реестра первичных сведений. При каждом запуске выполняются миграции и идемпотентный импорт двух разрешённых файлов из томов только для чтения с проверкой SHA-256. Первый реестр в пустой БД публикуется автоматически; последующие импорты не меняют витрину до отдельного администраторского переключения версии в `/catalog/manage/`.

## CI и внешний preview

GitHub Actions выполняет проверки и Docker build при PR/push. Интеграционные проверки требуют закрытый исходный `catalog_export_v4.csv` с разрешением на использование в CI; без него gate не считается пройденным. После успешной проверки `main` job `deploy` может вызвать URL деплой-хука, сохранённый в секрете GitHub `RENDER_DEPLOY_HOOK_URL`.

В репозитории есть шаблон `render.yaml` для сервиса Django и отдельного PostgreSQL в Render. Перед использованием нужно задать закрытые HTTPS-адреса `CATALOG_SOURCE_URL`/`RESEARCH_CLAIMS_URL` и проверенные SHA-256 обоих файлов. Контейнер скачает источники в закрытую временную область, сверит контрольные суммы и импортирует; при ошибке запуск остановится. Затем привязать **именно этот** репозиторий и ветку `main`, установить ограничения расходов и секрет деплой-хука в GitHub. Для CI задать одноимённые secret URL и variable checksum. Проверить HTTPS, опубликованный SHA (`git rev-parse HEAD`), `/health`, `/ready` и пути трёх объектов извне. Поле `autoDeploy: false` оставляет единственный trigger публикации после зелёных тестов CI.

На Render включено `ENFORCE_HTTPS=1`: Django перенаправляет HTTP на HTTPS за доверенным TLS-прокси и устанавливает краткосрочный HSTS. При локальном HTTP-тестировании и запуске Compose этот флаг не задаётся. Прежде чем использовать иной прокси, проверьте, что заголовок `X-Forwarded-Proto` устанавливается только доверенной инфраструктурой.

Пока провайдер не привязан и внешний адрес не проверен, онлайн-публикация имеет статус **blocked-by-access**. Конфигурация сама по себе не подтверждает существование работающего стенда. Для отката выбрать предыдущий проверенный commit/деплой в панели провайдера; перед изменением схемы БД проверить совместимость миграций. Закрытые исходные файлы и персональные данные не загружать в preview.
