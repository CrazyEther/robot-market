# Получение и проверка внешних сведений

Конкурсный `catalog_export_v4.csv`, список ссылок и полученные страницы хранятся вне Git в закрытом каталоге. Для получения и обработки используются `tools/source_research/collect.py` и `tools/source_research/curate.py`. Первый сохраняет исходные байты страниц с датой, URL, HTTP-метаданными и SHA-256; второй сверяет утверждения с исходными снимками и строками конкретной версии v4. В `claims_input.json` каждая строка содержит источник, объект, атрибут, значение, единицу, область действия, допустимое применение, цитату для проверки и точные номера записей каталога. Выход — `verified_claims.json` с каталоговыми идентификаторами и checksum.

Паспортная максимальная скорость (`manufacturer_max_speed_m_s`) и опубликованное время работы на заряде — характеристики точной модели, а не измеренная средняя скорость, доступность или время цикла на объекте. Для Ronavi интервал `runtime_80_to_20_h` относится только к заряду 80→20%. Расчёт парка получает эксплуатационную скорость, обслуживание, зарядные очереди и рабочие окна из паспорта площадки; он не подменяет их паспортным максимумом производителя. Новое исследование импортируется отдельным immutable `CatalogEvidenceBatch`, существующие ревизии проектов сохраняют прежний checksum сведений.

Для загрузки через сайт администратор с разрешениями на оба типа пакетов открывает `/catalog/manage/`. Перед загрузкой нового реестра он собирает и проверяет первичные снимки через `tools/source_research/`, утверждает SHA-256 выходного JSON в закрытой конфигурации `RESEARCH_CLAIMS_SHA256`, указывает основание использования и загружает файл. Каталог v4 допускается только с `CATALOG_SOURCE_SHA256`, утверждённым для окружения; изменение конкурсного CSV не служит способом исправления предложения. Импорт сверяет байты, схему, точные ссылки на строки v4 и сохраняет исходный файл в закрытой БД. Журнал показывает акторский импорт, а прямое изменение исторических строк в Django admin запрещено. Старые пакеты можно повторно загрузить для восстановления сырого файла без создания дубликатов. Загрузка через сайт не публикует даже первый пакет: сотрудник с правом публикации выбирает его и записывает причину. Начальный CLI-импорт при развёртывании закрепляет первую версию автоматически; следующие CLI-импорты не меняют указатель.

Для витрины используются только утверждения `product_copy`, `matching_limit`, `offer_specific` и проверенные ссылки производителя. Краткое описание `product_copy` привязано к точной модели и первичной странице; оно может заменить исходный текст карточки, но не исходную запись каталога. Противоречивое значение остаётся `blocked` и не попадает в сравнение характеристик. Цена из конкурсного CSV без валюты не является покупательской ценой; коммерческие суммы и условия берутся из отдельного проверенного утверждения. Старые версии реестра сохраняются для открытых проектов.

Покупательский список и прямые карточки показывают только семейства, у которых в выбранной версии реестра есть ненулевое проверенное утверждение `product_copy`, `matching_limit` или `offer_specific`, привязанное к конкретной исходной строке. Один лишь сайт бренда, запись конкурса или опубликованный кейс не создаёт карточку товара. Без проверенного реестра витрина отвечает 503; неподтверждённая карточка — 404. Исходные строки остаются в базе для последующего исследования и аудита. Категории в интерфейсе берутся из человекочитаемого подтипа или, при его отсутствии, типа изделия; описание показывается из проверенного `product_copy`, без подстановки конкурсного рекламного текста.

Для подбора процесс фиксируется в ревизии проекта вместе с измерениями владельца и источником каждого значения. Утверждение `candidate_application` связывает первичную страницу или опубликованный кейс с конкретной записью v4 и кодом операции; оно лишь включает модель в рассмотрение. `matching_limit` проверяет паспортный предел точной модели. Качественные ограничения принимают только подтверждённое `boolean` с паспортом производителя; отсутствие или противоречие любого обязательного условия даёт `requires_verification`, превышение известного физического предела — `reject`. Текущая ревизия использует сохранённый checksum реестра, а не новые сведения по умолчанию. Результат подбора не является расчётом парка или финансовым прогнозом.

Импорт отклоняет реестр, если для одного объекта, атрибута и точной строки одновременно есть `blocked` и `matching_limit`. При расхождении двух страниц производителя численное значение остаётся в журнале конфликта, но не попадает в характеристики карточки или условия подбора. Характеристика соседней модели хранится под отдельным атрибутом и не блокирует паспорт точной модели.

Складской подбор различает `pallet_floor_pickup` и `pallet_platform_transport`. Отрицательное паспортное `boolean` отклоняет только тот способ, который выбрал владелец объекта; положительный признак платформы сам по себе не подтверждает совместимость загрузки и снятия паллеты в конкретных точках. Выбор способа с источником сохраняется в паспорте задачи; старые ревизии без него остаются с неопределённым условием.

Выбор робота сохраняется как `robot_selection` в следующем неизменяемом снимке: точный `record_index` в версии v4, исходный ID, контрольные суммы каталога и реестра, все утверждения о применении, версию matcher, статусы и ссылки проверок. Смена операции или паспорта объекта удаляет активный выбор только из новой ревизии; историческая ревизия сохраняет прежний выбор. Интерфейс не использует исходный ID семейства как доказательство тождественной комплектации.

```powershell
$env:SOURCE_RESEARCH_DIR = 'D:\private\robot-market-research'
$env:CATALOG_SOURCE_PATH = 'D:\private\catalog_export_v4.csv'
python tools\source_research\collect.py
python tools\source_research\curate.py
Get-FileHash "$env:SOURCE_RESEARCH_DIR\verified_claims.json" -Algorithm SHA256
```

В `SOURCE_RESEARCH_DIR` должны быть `sources.json` и `claims_input.json`. Первый содержит список проверенных HTTPS-адресов с полями `id`, `object`, `kind`, `url`; второй — журнал отобранных значений. Собираемые материалы не добавляются в публичный репозиторий. Если страница изменилась, сбор создаёт снимок с новым хешем, а обработка повторно проверяет ссылку на него. Изменение значения или принадлежности модели требует предметного просмотра человеком, даже если цитата найдена автоматически.

Для CI секрет `CATALOG_SOURCE_URL` и переменная `CATALOG_SOURCE_SHA256` указывают на разрешённую копию v4; секрет `RESEARCH_CLAIMS_URL` и переменная `RESEARCH_CLAIMS_SHA256` — на проверенный реестр фактов. Файлы загружаются в временный каталог runner, проверяются по SHA-256 и не выводятся в журнал. Отсутствие файла или расхождение контрольной суммы останавливает проверку. Внешний сервис `render.yaml` требует оба закрытых URL и обе контрольные суммы; импорт создаёт неизменяемую версию утверждений, на которую ссылаются новые проекты. Реестр фактов не заменяет паспорт объекта или договор.

## Отдельное дополнение производителей

Производитель вне v4 поступает отдельным закрытым JSON с `source_kind: manufacturer_supplement`, списками `sources` и `products`. Модель задаётся `product_ref`, производителем, именем, вариантом и HTTPS-ссылкой; область применения ссылается на предметный процесс. Каждая числовая характеристика хранит исходное число и единицу, нормализованное значение, страницу PDF или HTML-источник и SHA-256 точных исходных байтов. Версия схемы 1 остаётся читаемой для существующих пакетов. Версия схемы 2 требует для каждой оферты `kind` (`purchase`, `raas` или `rental`), `price_basis` и `scope` сверх суммы, валюты, НДС, срока и первичного источника. Эти текстовые условия берутся из того же первичного документа; прежняя оферта версии 1 без них не показывается покупателю как сопоставимая цена. Отсутствие предложения оставляет список `offers` пустым и не создаёт нулевую цену.

Команда `python manage.py import_supplement MANIFEST --expected-sha256 SHA --source-asset source_ref=PATH [--source-asset source_ref=PATH ...] --rights-basis TEXT` архивирует закрытый JSON и все перечисленные первичные снимки атомарно. Для журнала берётся учётная запись ОС, выполняющая команду. Команда никогда не переключает витрину. Существующий v4 и сохранённые проекты не меняются. Отдельный указатель и акторский журнал предусмотрены для публикации после проверки прав на метаданные; до публикации дополнение не участвует в подборе и не показывается посетителю.

Для CI `SUPPLEMENT_MANIFEST_URL` (секрет) и `SUPPLEMENT_MANIFEST_SHA256` (переменная) дают закрытый файл; `python -m catalog.bootstrap_supplement` скачивает перечисленные в нём первичные HTTPS-источники и сверяет байты. Тесты получают `SUPPLEMENT_MANIFEST_PATH` и `SUPPLEMENT_ASSET_DIR`. Исходные HTML/PDF, JSON и их копии в БД/резервных копиях остаются в закрытом контуре. Локальная версия v1 содержит Aethon T3, v2 добавляет TLD EZTow; в обоих пакетах отсутствуют коммерческие оферты. T3XL с конфликтующим заголовком PDF не импортирован как подтверждённая комплектация.

Для ручной загрузки закрытого дополнения оператор с правом `catalog.add_supplementbatch` открывает `/catalog/manage/supplements/`, передаёт JSON, его ожидаемый SHA-256 и все перечисленные в нём первичные HTML/PDF файлы. Имена загружаемых файлов не задают их принадлежность: сервер вычисляет SHA-256 содержимого, сопоставляет с манифестом, проверяет размер/схему и атомарно сохраняет пакет с акторским журналом. Загрузка не меняет витрину. Оператор с отдельным правом `catalog.change_supplementpublication` выбирает сохранённую версию, указывает основание и подтверждает право публичного отображения метаданных; переключение проверяет сохранённые байты и нормализованные строки. Для локальных тестов используется изолированная БД. Публичные права на T3/EZTow ещё не подтверждены, поэтому реальная публикация их метаданных не выполнена.

Первичный сайт поставщика подтверждает только опубликованное им заявление. Дубли, несовпадение вариантов модели, внутренние противоречия страницы, диапазоны тарифов и неизвестные валюта/НДС фиксируются отдельно. Нельзя переносить показатели чужого объекта на нового клиента, автоматически считать `fit` или финансовый результат. Вопрос о праве публикации исходных документов решается до размещения их байтов в открытом хранилище.
